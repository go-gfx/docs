2D on the GPU

2D on the GPU

github.com/go-gfx/gpu2d (v0.6.1) renders 2D on the GPU, in pure Go. A frame is one backend-neutral list of instances, one per primitive, 48 bytes each:

  • Rasterize executes it on the CPU and is the reference.
  • Package webgpu draws it in the browser through go-gfx/webgpu.
  • Package metal draws it with a compute kernel through go-macos/metal.
l, err := gpu2d.NewList(1920, 1080)
l.FillRect(gpu2d.Rect{W: 1920, H: 1080}, gpu2d.RGBA{R: 236, G: 236, B: 236, A: 255})
l.PushClip(gpu2d.Rect{X: 20, Y: 20, W: 400, H: 300})
l.FillRoundRect(gpu2d.Rect{X: 40, Y: 40, W: 120, H: 32}, 8, gpu2d.RGBA{R: 0, G: 122, B: 255, A: 255})
l.PopClip()

err = l.Rasterize(buf)       // CPU reference
r, err := metal.New(1920, 1080)
err = r.Draw(l)              // the same frame on a Mac's GPU

Since v0.3.0, Draw is Submit plus Wait, and the pair overlaps the CPU with the GPU (see Asynchronous submit).

The reference

The list draws these primitives, all under nested translations and clips:

  • fills and one-pixel outlines of rectangles, square or with anti-aliased rounded corners, with any number of rings;
  • since v0.2.0, glyph masks (DrawMask), scaled images (DrawImage), and paths (DrawAlpha, fed by the go-gfx/gfx/vector rasterizer). Masks and images travel in a per-frame data arena that the GPU reads.

These are the primitives of go-widgets/painter’s PixelPainter, and Rasterize reproduces it byte for byte. The internal/parity test compares the two over 3000 random scenes, with 51,947 instances including 2970 masks, 2999 images and 11,251 paths.

Asynchronous submit

On a small frame the GPU is not the cost: an empty dispatch alone is 0.41 ms, and Draw blocks the CPU for all of it. Renderer.Submit bins and packs a copy of the list into one of two slots of input buffers, sends it and returns; Wait collects the oldest frame:

err = r.Submit(l) // returns at once; l may be Reset and re-recorded
record(l)         // the next frame, while the GPU draws this one
err = r.Wait()
frame := r.Pixels() // safe to read only when nothing is in flight

Two frames may be in flight, compositing in submission order over the same Pixels. A third Submit or a Draw with frames in flight is ErrBusy, a Wait with none is ErrNothingInFlight, and Close waits first. It rests on Device.Submit and Pending.Wait in go-macos/metal v0.4.0. A 960 × 2834 widget frame on an M4 Max, with 1.5 ms of CPU work per frame (the size of the gallery’s recording), median of 10 interleaved rounds at a 1-minute load of 8.0 to 8.2, so indicative:

CPU work per frameDrawSubmit / Wait
01.31 ms1.33 ms

Recording and binning allocate nothing in steady state. Since go-macos/objc v0.12.0’s allocation-light message sends, a whole Submit costs 21 allocations.

Submit’s cost is almost all CPU-side packing: binning the list into 16 × 16 tiles and copying it into the slot. Encoding and Metal’s commit add about 14 µs. Since gpu2d v0.6.1, binning runs in plain loops rather than a callback per (instance, tile) pair. Measured on an M4 Max, 8 interleaved rounds at a 1-minute load of at most 8:

Presenting in a browser canvas

Since v0.5.0, webgpu.Renderer.Present(surface) copies the renderer’s target into the surface’s current texture on the GPU, so the frame goes to the canvas without coming back to Go memory. Call it after Draw; the browser shows the canvas at the end of the task. The surface must be the renderer’s size and be configured with webgpu.CanvasDescriptor():

desc := gpu2dwebgpu.CanvasDescriptor() // the browser's preferred canvas format
s, err := device.NewSurfaceFromCanvas(offscreen, desc)
err = r.Draw(list, nil)
err = r.Present(s) // byte-exact in either format

Since v0.6.0, CanvasDescriptor follows getPreferredCanvasFormat:

  • bgra8unorm (macOS, Windows): Present draws the target into it with PresentShader, a textureLoad at each pixel. unorm8 → float → unorm8 gives back the same byte.
  • rgba8unorm elsewhere, with COPY_DST: Present copies with copyTextureToTexture, which is byte-exact because it is the target’s own format.
  • Anything else is refused with ErrSurface.

The preferred format matters, because a canvas in another one costs an extra copy in the browser’s compositor. internal/presentbench measured it with a real page drawing WidgetFrame at 4K, timed until the GPU finished, over 8 interleaved rounds per platform, with the adapter logged in each:

4K framergba8unormbgra8unorm
Apple M4 Max, macOS (prefers bgra8unorm)1.053 ms0.792 ms (−24.8 %)
AMD Radeon PRO W7700, Linux on Vulkan (prefers rgba8unorm)0.704 ms1.083 ms (+53.7 %)

The preferred format wins on both, although they are opposite formats. That is why CanvasDescriptor asks the browser instead of fixing one.

A caller that replaces a renderer, for instance when a canvas is resized, calls Renderer.Destroy() on the old one (v0.5.1). It releases the buffers and the target texture and refunds them to the device’s quota; without it each replacement keeps its memory charged. The renderer must not be used afterwards, and a second Destroy is harmless. The pipeline is not refunded, because WebGPU has no way to destroy one. go-widgets/webcanvas v0.9.0 presents this way.

The Metal kernel blends with the reference’s integer arithmetic. WebGPU uses fixed-function blending, which rounds where PixelPainter floors a + dst·(255−a)/255. A window surface is opaque, so the difference does not show there.

Bounds

  • Every coordinate lies within ±2^24, the range in which float32 holds every integer exactly.
  • Translations and clips saturate, and ring counts are capped.
  • Binning for the Metal kernel is limited by MaxBinned, and a list past it is refused before anything is allocated.
  • FuzzList checks that nothing is recorded past these bounds and that nothing is written past the surface.

One coverage, written in WGSL

Since v0.5.2 the Metal kernel’s Inst, cornerCenter and coverage are not written by hand. They are generated from the WebGPU shader by wgsl’s msl package (go generate ./metal writes metal/coverage_gen.metal), so the coverage arithmetic exists once, in WGSL, next to the Go reference.

  • Byte-identical: the kernel matches the CPU reference, with max |Δ| 0 over 3,686,400 channels.
  • Drift guard: TestCoverageMetalIsGenerated fails on every platform when the WGSL changes without the Metal file being regenerated.

The go-widgets painter.Painter adapter (go-widgets/gpupainter) and presentation are done: a CAMetalLayer in go-widgets/window v0.90.0, and the browser canvas in go-widgets/webcanvas v0.9.0.

The design is in docs/DESIGN.md.
